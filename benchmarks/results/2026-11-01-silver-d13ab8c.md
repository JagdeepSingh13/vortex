## Notes on these results

- **Run with `ROWS_PER_RUN=1`**, i.e. one silver run per bronze snapshot, on a small dataset: a 2-minute load at 1,000 orders/s (56,341 trades), deliberately light for this laptop.
- **At this size a run is fixed overhead, not work per row.** Runs of 6,937 to 56,341 rows all took 4.6–6.8 s, plus Spark warm-up in the first run (11.9 s). The time goes to three Iceberg commits (silver, rejects, progress), metadata reads and planning the MERGE. The rows/s column therefore measures overhead, not throughput.
- **Not answered here:** whether a run gets slower as silver grows (the MERGE joins the new rows with silver). 56k rows is too small to show it; that needs a bronze of millions of rows.
- **The full rerun** (every key already in silver, the worst case of crash recovery) inserted 0 rows in 4.6 s.
- **End to end, `make silver` from the command line took 28–50 s per run** on the same day (silver progress table, 06:40 and 06:42 UTC), with the bronze stream running at the same time. Most of that is starting a fresh Spark JVM, so on this laptop silver can be scheduled every few minutes, not every few seconds.
